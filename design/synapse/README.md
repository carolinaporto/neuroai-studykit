Synapse is the visual system for a personal study kit built for a Harvard course on the foundations of natural and artificial intelligence — the weekly recall quizzes, class sources, insight notes and public research homework live under it. Built from scratch for this one course site: there is no existing codebase or brand to draw from, so every token below is a deliberate starting point, not a migration.

## Content fundamentals

Write in plain, first-person study language, not marketing copy: "Week 03 — Learning & Plasticity," not "Unlock the power of neural learning." Section names are nouns, not verbs: Sources, Quizzes, Notes & Insights, Homework — never "My Sources" or "Quiz Time!". Keep numerals for weeks and scores (`Week 3`, `7/10`), spelled out for everything else. No emoji anywhere in the interface; a locked section is marked by the lock glyph and the word "Private," never a 🔒 emoji. Tag notes and homework by discipline using the course's own three lenses — `Neuroscience`, `Computer Science`, `Psychology` — set in `tag`, never invented category names.

## Visual foundations

**Color.** The page sits on `surface-50`, a warm paper ground, never plain white — it is what separates a personal study site from a generic app shell and echoes the printed course readings. Cards and the nav rail sit one step up on `surface-100`; `surface-200` is the resting fill for anything hovered or locked. Text is `ink` for primary copy and `ink-soft` for meta (timestamps, byline, source counts) — never gray-on-gray; `ink-soft` holds 5.5:1 on both `surface-50` and `surface-100`.

Two accents carry two different meanings and are never swapped for each other. `accent-neuro`, a slate indigo, is the interactive color: links, the active nav item, primary buttons, the quiz progress fill. `accent-warm`, a muted brick — a quiet nod to Harvard without borrowing its crimson outright — marks only what is public: the Public badge on a homework card, the GitHub and live-link icons, homework tags. If a control is clickable and not specifically "this is public," it is `accent-neuro`, not `accent-warm`. `success` is a teal-shifted green and `danger` a warm red-orange, chosen so the pair reads apart under red-green color blindness; never rely on `success`/`danger` color alone — pair each with a word ("Correct," "Try again") or an icon, as the QuizCard does.

**Type.** Headings are set in `Newsreader`, a serif — it gives the site the editorial, printed-course feel of a reading packet rather than a SaaS dashboard, used for `display`, `h1`, `h2` and `h3`. Everything interactive and informational is `IBM Plex Sans` (`body`, `body-sm`, `label`, `caption`, `button`) — a technical, humanist sans that carries the computer-science half of the course without reaching for an overused UI font. `IBM Plex Mono` (`tag`, `code`) is reserved for small, precise marks: week chips, scores, the AccessBadge label, repo paths — never body copy. `label` is the only uppercase style in the system (apply `text-transform: uppercase` in markup, the token does not do it for you) and is reserved for nav items and eyebrows; do not set a heading in `label`.

**Spacing and shape.** Build every layout on the `space-1`–`space-8` scale, never an arbitrary pixel value. Cards and buttons round to `radius-md`; panels and the nav rail to `radius-lg`; chips, tags and the AccessBadge to `radius-pill`; inputs and small tags to `radius-sm`. Elevate with `shadow-sm` at rest and `shadow-md` only for things that float above the page (the sign-in panel, an open menu) — never stack both on the same element, and never use a shadow to imply a locked state; use `surface-200` and the lock glyph for that instead.

**Borders over shadows for structure.** Prefer a `border-subtle` hairline to a shadow when separating a list of sources or dividing a week from the next; reserve `border-strong` for input outlines and anything whose border is itself meaningful (a selected quiz option, an invalid field).

## Iconography

No icon library ships with this system yet — use a single-weight line icon set (Lucide or Phosphor, regular weight, 20px, 1.5px stroke) and keep every icon that size across the site. Icons inherit `currentColor`; set that color from the token the icon sits in (an `ink-soft` icon next to meta text, `accent-warm` for the GitHub/external-link glyphs, `on-fill` on a filled button). The lock glyph is the one icon with a fixed meaning in this system: it appears only on private sections and rows, paired with the word "Private" in `caption`, and never elsewhere.

## Access and privacy

This is the one pattern the whole site is organized around, so it gets its own rule: Sources and Quizzes are private (class materials cannot be public); Homework is public by default (the research write-ups that make up the semester portfolio); Notes & Insights is private unless a specific note is marked public. Mark state with the `AccessBadge` component and `accent-warm` for "Public," `ink-soft` + the lock glyph on `surface-200` for "Private" — never with color alone, and never by hiding the badge. A signed-out visitor sees every private section in its locked state (title, week, lock glyph) rather than not seeing it at all, so the site still reads as a full portfolio from the outside.

## Intentional additions

There is no existing codebase to enumerate a component inventory from, so this system ships exactly the pieces named in the brief and nothing standard added on top: `SiteNav` (the menu, with per-section lock state), `WeekHeader` + `SourceItem` (sources grouped by week), `QuizCard` (the weekly recall check, its locked/available/completed states), `InsightNote`, `AccessBadge` (the shared Public/Private primitive `SiteNav`, `SourceItem`, `QuizCard`, `InsightNote` and `HomeworkCard` all use), `HomeworkCard` (the public portfolio entry) and `Button`. Build further components — a search field, a quiz-answer input, a toast — only once the site actually needs them, from these same tokens.
